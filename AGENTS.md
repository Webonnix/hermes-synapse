# Инструкции для AI-агентов, работающих в этом репозитории

Общая точка входа для Claude Code, Codex, Cline и любого другого агента.
Файл публикуемый: сюда не попадают адреса машин, токены, пути к личным
каталогам и локальные особенности рабочей станции.

## Читать перед правкой

1. `README.md` — что это за система.
2. `docs/CONTRACTS.md` — индекс «подсистема → контракт». **Перед правкой
   подсистемы прочитай её контракт.** Большая часть регрессий здесь случалась
   не из-за сложного кода, а из-за неявного контракта, о котором правщик не знал.
3. `docs/GUIDELINES.md` — как довести изменение до готовности с первого раза.
4. `../docs/product-and-architecture-audit.md` — приоритеты P0/P1/P2 и модель угроз
   (продуктовые документы лежат в рабочем каталоге рядом с репозиторием, не в нём).

## Как запускать проверки

```bash
# Бэкенд (Python 3.11+). Из каталога репозитория:
python -m pytest backend/tests -q
```

```bash
# Фронтенд. Хостовый node может быть слишком старым — гоняй в контейнере.
docker run --rm -v "$PWD/frontend":/app -w /app node:20 sh -c "npm ci && npm run lint && npx vitest run && npm run build"
```

Правила:

- Node **20**, образ **Debian** (`node:20`), не alpine: vitest на alpine не
  запускается. Сборка образа фронтенда на alpine работает — это только про тесты.
- `npx tsc --noEmit` — **не** то же самое, что сборка образа. Оба должны проходить.
- Тесты гоняются в одноразовом окружении, **никогда** в живом бэкенде: они
  пишут в БД и в каталоги данных.
- Для экспериментов с состоянием используй временный каталог данных, а не
  рабочий: код читает и пишет реальные сессии, ключи и историю.

## Что нельзя делать

- Логировать полный prompt, tool arguments, содержимое `.env`, ключи, токены и
  пароли. Диагностика хранит метаданные, а не тела запросов.
- Расширять `allow_origins` до `*` вместе с credentials.
- Добавлять `manager.broadcast` для трафика чата — см. контракт WebSocket.
- Держать `sqlite3` вызовы в горячем пути без обработки ошибок: диагностика
  падает молча и не уносит с собой пользовательский ход.
- Править `docker-compose.yml` в расчёте на то, что это изменит настройки LLM:
  `app_settings` в БД перекрывает переменные окружения.

## Стиль вклада

- Одно логическое изменение на PR; несвязанный рефакторинг — отдельно.
- Пиши код так, как написан соседний: та же плотность комментариев, те же имена.
- Комментарий объясняет **почему**, а не **что**. Особенно ценно объяснение,
  какой сбой этот код предотвращает.
- Для изменения поведения — тест, который **падает до** правки и проходит после.
- Обновляй документацию, если меняешь запуск, развёртывание, контракты или
  пользовательские сценарии.
